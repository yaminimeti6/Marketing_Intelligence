# Creative Library

Open `/creative-library`. Owners/admins can upload images and short videos, edit title/tags/notes, archive/restore and permanently delete archived assets after explicit confirmation. Workspace members can search, filter, preview and download. Private endpoints check current session and workspace membership on every request. No public asset URLs or external object-storage account is required.

Accept JPEG, PNG and static WebP up to 2,000,000 input bytes; MP4/WebM up to 4,000,000 bytes. Raster images are actually decoded, limited to 16 megapixels and dimensions at most 8192, auto-oriented, stripped of metadata and saved as optimized WebP (quality 90). This changes compression/format; download the original separately if required. Transparency is retained. Thumbnails are separately generated, at most 320x240 and 100 KB. SVG, HTML, GIF and animated images are rejected. See [Sharp constructor](https://sharp.pixelplumbing.com/api-constructor/) and [output options](https://sharp.pixelplumbing.com/api-output/).

Videos receive container-header checks, not full codec validation, transcoding, malware scanning or metadata stripping. Playback depends on browser/codec support. They use authenticated byte-range media delivery; video preload is disabled until user interaction. No video thumbnail is generated. Neither images nor videos are published to Meta or a storefront.

AI Images results have an explicit Save to Creative Library button. The existing generated JPEG remains downloadable; saving creates the normalized WebP library version. No new generation request or paid AI call is made by saving. The AI-labelled source is user-provided metadata, not cryptographically verified provider provenance. Briefs and credentials are not saved in the library.

The free-hosting storage budget is 50 assets and 30,000,000 bytes per workspace, counting archived files and thumbnails. Content is stored in PostgreSQL bytea, so files count against database storage/backups. Quotas are checked under a workspace lock; content hashes deduplicate within a workspace. Re-uploading identical normalized content returns the existing record, including archived records, without changing metadata. Archived items still consume quota; permanent deletion frees space and removes the stored file and thumbnail. Saved assets have no connection to ad metrics, campaign publication or externally downloaded copies.

Metadata allows a 100-character title, eight comma-separated tags of up to 24 characters (including Gujarati), and 500-character notes. Text is rendered as text, not HTML. Updates check revisions and reject conflicting edits. Migration 023 enables tenant RLS and owner/admin writes; audits record save, metadata, archive/restore and deletion. No uploads, demo assets or provider requests are seeded by installation.
