# Scheduled Reports

Open `/scheduled-reports`. An owner/admin can create up to 20 schedules: daily, Monday weekly or first-of-month, at an hour in UTC. For example, 08:00 UTC is 13:30 India time. Reporting dates use the chosen Meta account timezone, independently of scheduling time. Choose the previous 1, 7 or 28 completed days, one account or all matching-currency/timezone accounts. Current metrics are campaign spend, impressions, clicks, provider conversions/value and ROAS. Shopify and profit report schedules are not implemented.

Each run creates an immutable CSV snapshot of imported data and records coverage, generation time, last syncs and definition. Complete coverage plus successful sync within 15 minutes is required; incomplete, stale, revoked or oversized sources produce an unavailable run, not a zero-valued report. Runs do not initiate imports or contact Meta. A fresh snapshot with unknown optional metrics uses N/A. At most 2 MB and 30 recent snapshots per schedule are retained. All workspace members can read/download; owner/admin access is required to create, pause, enable or generate. Download links require login and membership and contain no bearer token.

Select a current workspace member and explicitly authorize email to queue report-ready notifications. Only successful snapshots of enabled schedules queue mail. Notifications include a sign-in-protected report link, no attachment or performance values. Delivery requires RESEND_API_KEY, verified EMAIL_FROM and public HTTPS APP_URL in the worker environment. Provider acceptance is displayed separately from inbox delivery, which is not verified. Removed recipients are skipped. Pausing a schedule skips pending mail; an already claimed send may still finish. Pending notifications older than 24 hours expire.

Run one pass with `npm run worker:reports`. `npm run workers:watch` includes reports automatically, using REPORTS_WORKER_USER_ID, or falling back to META_WORKER_USER_ID / SHOPIFY_WORKER_USER_ID. This identity must retain owner/admin membership. For cloud data, run `node --env-file=.env.netlify --experimental-strip-types scripts/reports-worker.ts` (one pass), or start the watch runner with the cloud environment loaded. Netlify request hosting does not run this worker continuously. A free external runner must remain active for automated reports; this feature does not provision hosting or a cron service.

Schedules start at their next future slot. On restart, a late schedule creates one latest snapshot using the actual generation day's reporting window and advances to the next slot; missed intervals are not backfilled. A row lock, unique slot and transaction covering snapshot plus next-run update prevent duplicate publication. Failed database work rolls back and retries on a future worker pass. Generate now works while paused (in-app only); it does not shift the schedule, and is limited to once per minute per schedule.

Email outbox claims commit before the external POST. Only one provider attempt occurs, using a per-run idempotency key. Rejections are failed; network errors, 5xx and malformed success responses are uncertain. A crashed worker can leave sending status; no automatic resend occurs. Inspect Resend before generating a new notification. Fix sender/configuration errors before the next run. No webhook-based delivered/bounced tracking or automatic email retries are included.

Migration 021 provides tenant-isolated schedules, immutable run snapshots and a separate email outbox. Audit events record schedule changes and report generation. No schedules, recipient selections or test emails are seeded.

Provider reference: [Resend idempotency keys](https://resend.com/changelog/idempotency-keys). The application keeps its own send claims and does not rely on the provider retention window for retries.
